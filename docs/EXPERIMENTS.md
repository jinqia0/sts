## EXP-01 弱怪池单场遭遇（2026-10-05）

**状态**：✅ 完成，模型 `models/weak_pool_1m_hp76.zip`

### 场景设定

| 项 | 设定 |
|---|---|
| 牌组 | 铁甲战士初始牌组（5 Strike / 4 Defend / 1 Bash），固定不变 |
| 遭遇 | 每局从弱怪池**均匀随机抽一种**：cultist / jaw_worm / louses / slimes_s / fungi_beast |
| 规模 | 单场战斗，无跨场状态（HP/能量/牌堆每局重置） |
| 环境 | `StsBattleEnv(encounter="random")`，观测 691 维 int32，动作 Discrete(61) |
| 奖励 | **战损口径**：终局 = 剩余 HP / 80（胜），败 0，进行中恒 0 |
| 算法 | MaskablePPO（sb3-contrib 2.9.0），MlpPolicy 2×64，CPU |
| 超参 | lr=3e-4，n_steps=512，batch=256，gamma=0.99，gae_lambda=0.95，ent_coef=0.01 |
| 种子 | 训练 10_000；周期/最终评估 70..99 |

### 决策演进（为什么要这样设定）

1. **连打 5 场 → 随机单场**：最初设定为「连打 5 场弱怪、HP 继承不回血」。
   发现 5 种弱怪之间无配合关系，连打序列本身无策略含义，只拉长信用分配
   距离、增加学习难度，故简化。教训：**不要给场景加无策略含义的结构**。
2. **±1 稀疏 → 战损口径**：±1 奖励下 50k 步胜率即 1.00（弱怪池无死亡威胁，
   胜率指标失效），且赢后保血无梯度，PPO 停在 71.2 HP 追不上 heuristic。
   改为终局 HP 比例后，保血有持续梯度且无歧向（胜率保持 1.00，无拖时间
   行为）。教训：**奖励要指向真正关心的量；胜率饱和的场景换 HP 口径**。

### 训练曲线（1M 步，主指标：评估平均剩余 HP）

```
  50k  72.3      550k  75.5
 100k  72.6      600k  76.0
 150k  73.7      650k  76.2
 200k  75.0      700k  76.2
 300k  75.0      800k  76.3
 400k  75.7      950k  76.4  ← 收敛平台 ~76.1±0.2
 500k  75.7     1000k  76.1
```

300k→1M 仅 +1.0，且曲线最后 40 万步只涨 0.1——弱怪池天花板已到。

### 最终结果（评估种子 70..99）

| 策略 | 剩余 HP / 80 | 回报 | 胜率 |
|---|---|---|---|
| random | 62.0 | 0.775 | 1.00 |
| heuristic | 75.5 | 0.944 | 1.00 |
| **MaskablePPO (1M)** | **76.0** | **0.950** | 1.00 |

分遭遇（PPO / heuristic）：

| 遭遇 | PPO | heuristic | 评 |
|---|---|---|---|
| louses | 77.1 | 72.9 | PPO 胜 |
| slimes_s | 78.9 | 76.4 | PPO 胜 |
| fungi_beast | 79.7 | 80.0 | 平 |
| cultist | 79.0 | 78.0 | （n=1 无统计意义） |
| jaw_worm | 68.9 | 72.9 | heuristic 胜 |

### 结论与遗留

- **验收达成**：显著超 random（+14.0 HP），总体小胜 heuristic（+0.5），
  分遭遇 3 胜 1 平 1 负。ROADMAP 第 2 步 ✅
- **jaw_worm 是唯一短板**（-4.0）：池中唯一需要跨回合规划（何时囤防 vs
  输出）+ 马尔可夫随机意图的怪。归因候选：小 MLP 容量、无记忆快照观测
  （无意图历史段）、或样本仍不足。**未做单怪专家消融验证**（讨论过
  方案：单遭遇训练对比混合训练，因与卡组泛化设计冲突未执行）
- **已讨论未采纳**：per-monster 专家 policy + 按需路由——技术上可行，
  但与「卡组分布采样训练 → 评估没见过的卡组」的 Phase 2 前提冲突，
  留作 oracle 阶段的策略缓存备选
- **场景饱和**：弱怪池对任何策略都 100% 胜率，天花板 ~80（满血），
  无继续优化空间。下一步（第 3 步）加精英怪让胜率/战损重新成为有效信号

## EXP-02 弱怪池单场遭遇 + 怪物种类 one-hot（2026-10-05）

**状态**：🔄 训练中（与 EXP-01 唯一变量：观测含种类段）

### 改动

EXP-01 的遗留问题之一：观测没有显式怪物种类，策略只能从
（敌人数, max_hp, 意图模式）特征反推怪种——5 种弱怪下可分但费样本，
怪池扩大后必然碰撞。本实验在每个敌人槽加 32 维种类 one-hot
（玩家可见信息：名字/立绘，白名单内）。

实现要点（`sts/env.py`）：
- `MONSTER_INDEX` 词表与 `CARD_INDEX` 同规则：怪名 → 稳定 ID，
  只向后追加永不重排；未收录怪该段全零（特征兜底）
- 观测构造 `monster_index(m.name)` 查词表点亮 one-hot——名字只是
  字典键，**模型层面只见 ID**（与卡牌编码同构）
- 词表 32 位覆盖全游戏怪池；观测 691 → **851** 维
- 首版曾用 `display_name` 括号解析英文名，被嵌套括号
  （`酸液史莱姆（小）(Acid Slime (S))`）坑出 bug，改用 Monster
  子类的 `name` 类属性直查——教训：**能走结构化属性就不做字符串解析**

### 配置（其余与 EXP-01 完全一致）

| 项 | 设定 |
|---|---|
| 观测 | 851 维 int32（EXP-01 的 691 + 种类 32×5 槽） |
| 奖励 | 战损口径（同 EXP-01） |
| 算法/超参 | MaskablePPO 同 EXP-01 |
| 规模 | 1M 步，每 50k 评估（种子 70..99） |

### 训练曲线

```
  50k  73.0   400k  76.2   750k  76.4
 100k  73.6   500k  75.9   900k  76.4
 150k  74.4   600k  76.4  1000k  76.5（收敛）
 200k  74.9   650k  76.1
```

同期对比 EXP-01：50k 73.0 vs 72.3（+0.7）——起点略好，符合
「不用学反推怪种」的预期。

### 结果（模型 models/weak_species_1m_hp765.zip）

| 策略 | 剩余 HP / 80 | 回报 |
|---|---|---|
| random | 62.0 | 0.775 |
| heuristic | 75.5 | 0.944 |
| PPO 无种类（EXP-01） | 76.0 | 0.950 |
| **PPO 种类 one-hot** | **76.5** | **0.956** |

分遭遇（PPO 种类版 / 无种类版 / heuristic）：

| 遭遇 | +种类 | 无种类 | heuristic |
|---|---|---|---|
| louses | 78.3 | 77.1 | 72.9 |
| slimes_s | 79.1 | 78.9 | 76.4 |
| jaw_worm | 69.5 | 68.9 | 72.9 |
| fungi_beast | 79.7 | 79.7 | 80.0 |

**结论**：+0.5 总体提升（76.0→76.5），所有遭遇无一退化。
jaw_worm 短板仅 +0.6（68.9→69.5）——种类 ID 消除了「认怪」的
学习成本，但**没有解决跨回合规划问题**（短板主因是无记忆快照观测，
非怪种不明）。观测布局变更为 851 维后，691 维旧模型与本代码不再
兼容（复现旧模型需 checkout 提交 377af21）——这是观测版本化的
首次实际代价，以后动观测布局必须起新实验编号并记录兼容性。

## EXP-03 消融：怪物种类 ID 的信息价值（2026-10-05）

**状态**：✅ 完成，模型 `models/weak_shuffled_v1.zip`

### 设计

单变量消融：种类 one-hot 段给真 ID 还是乱序 ID，其余全部一致
（怪池/奖励/观测布局 851 维/1M 步/超参/评估种子 70..99）。

- 对照组：`weak` 场景（真 ID，结果复用 EXP-02：76.5）
- 实验组：`weak_shuffled` 场景——**每局 reset 重洗** MONSTER_INDEX
  值域映射（用户选定：切断最彻底的方案，连一一对应都没有，
  种类段退化为每局变化的纯噪声；np_random 派生，同种子可复现）

实现：`ScenarioSpec.species_shuffle` 字段 → env 每局重洗映射，
观测构造查乱序表。开关走场景配置（scenarios.py），代码零侵入。

### 结果（评估种子 70..99）

| 组 | 剩余 HP / 80 | 回报 |
|---|---|---|
| 真 ID（EXP-02） | 76.5 | 0.956 |
| **乱序 ID（本实验）** | **76.0** | **0.950** |
| 无种类（EXP-01，691 维） | 76.0 | 0.950 |

乱序组分遭遇与无种类组几乎复刻（jaw_worm 67.8 vs 68.9，
louses 78.3 持平，slimes_s 79.1 持平）。

### 结论

1. **种类信息净贡献 ≈ +0.5 HP**（76.0→76.5），三角验证一致：
   真 ID 对无种类、真 ID 对乱序的差几乎相同
2. **噪声段无害**：策略学会忽略每局变化的乱序位，没有掉到
   无种类水平之下——观测设计对「坏特征」稳健，不是脆弱平衡
3. **置信度有限**：+0.5 接近 30 局评估的抽样噪声（±1~2 HP），
   要硬结论需多种子重复训练取均值。弱怪池语境下收益也确实小
   （天花板 80，怪间行为差异不大）
4. **真正值得重做的场景**：精英怪/Act 1 后期怪池——「认错怪」
   代价是质的（Nob 惩罚技能牌 vs Sentry 分身），种类 ID 的价值
   预计远大于本场景的 +0.5

### 训练曲线要点

乱序组 50k 即 74.2（比真 ID 组同期 73.0 还高——初期噪声段反而
带来一点探索性），后期收敛到 75.9±0.2 平台，无明显平台差异。

## EXP-04 迷你局全内容训练（2026-10-08）

**状态**：✅ run_v1 完成（2M 步）；Boss 专家与网络扫描由接续链推进中

### 场景设定

| 项 | 设定 |
|---|---|
| 结构 | `StsRunEnv` 迷你局：3 弱怪 → 精英 1 → 2 强怪 → 精英 2 → Boss（Act 1 池） |
| 局外 | 掉落预设全源码化（药水 40%+blizzard、卡牌 3/37/60+保底、精英遗物 50/32/17、火堆 30%×3）；HP/牌组/遗物/药水跨场；燃烧之血 |
| 奖励 | **逐场剩血求和**，归一化基数固定 80（2026-10-08 用户纠错：解耦 max_hp——Feed/果汁的增长不稀释奖励）；败场 0 |
| 选牌 | 前 3 场必选 1 张、后期 50% 跳过（随机） |
| 观测/动作 | 12444 维 / 120 动作（5a/5b 全量环境透传） |
| 算法 | MaskablePPO，**[1024, 512]×(pi/vf) 26.6M 参数**（观测 12444 维，[64,64] 是瓶颈层） |
| 超参 | lr=3e-4，n_steps=2048，batch=512，**γ=0.995**（跨场 credit），ent_coef=0.01，OMP_NUM_THREADS=4 |
| 种子 | 训练 10_000；周期评估 70..79（10 run）；最终评估 70..99（30 run） |

### 训练曲线（主指标：周期评估平均奖励，上界 8）

```
100k  2.65 │ 600k  2.92 │ 1100k 3.69 │ 1600k 3.25
200k  2.97 │ 700k  2.96 │ 1200k 3.35 │ 1700k 3.16
300k  3.02 │ 800k  3.80 │ 1300k 3.19 │ 1800k 3.92 ← 峰值
400k  3.23 │ 900k  3.32 │ 1400k 3.15 │ 1900k 3.66
500k  2.93 │ 1000k 3.83 │ 1500k 3.52 │ 2000k 3.55
```

500-700k 平台（~2.9）后突破；1M 后在 3.1~3.9 震荡带，无发散。
通关率：900k/1500k/1800k/1900k 各 10%（10 run 评估，小样本波动）。

### 最终对比（30 run，种子 70..99）

| 策略 | 平均奖励 | 通关率 | 最远场次 | 死亡分布（0 起） |
|---|---|---|---|---|
| random | 1.66 | 0% | 6 | {0:1, 1:2, 2:6, **3:18**, 4:2, 5:1}（死于精英 1） |
| heuristic | 3.00 | 0% | 8 | {**3:18**, 4:6, 5:4, 6:1, 7:1}（同样死于精英 1） |
| **MaskablePPO run_v1** | **3.11** | 0% | 8 | {1:2, 2:2, 3:7, 4:7, 5:6, **7:6**}（半数死于 Boss 前） |

### 结论与教训

1. **PPO ≥ heuristic（3.11 vs 3.00），胜在死法**：heuristic 60% 死在精英 1
   （场次 3），PPO 只有 23%——它学会了跨场保血/选牌下的资源管理，
   半数 run 活到 Boss 门口。但 30 run 终局对照通关 0%：Boss 战是
   明确短板（这正是 Boss 专家独立训练的动机，`sts/boss_env.py`）。
2. **奖励口径坑（用户抓出）**：初版逐场 HP/max_hp——Feed/果汁涨上限
   反而稀释奖励。改为固定基数 80 + max_hp 跨场同步后修正。
3. **工程坑两只**：(a) torch/OpenMP 线程活锁（340k 步卡死 48 分钟，
   CPU 满载零输出）——`OMP_NUM_THREADS=4` + 心跳看门狗
   （120s 无心跳 → 栈转储 + fail fast）；(b) run 层 terminated 语义
   （中间场胜利 ≠ episode 终止）。
4. **网络规模**：26.6M 参数在 12444 维观测下无瓶颈迹象（ev≈0.94
   全程）；网络大小扫描（256,128 / 512,256 / 1024,512 / 1024,512,256
   各 1M 步）由接续链补全，结论待录。

## EXP-05 网络大小/深度/步数扫描（2026-10-08）

**状态**：✅ 完成。场景/超参与 EXP-04 完全一致，仅变网络与步数。

### 结果（30 run，种子 70..99）

| 模型 | 网络 | 参数 | 步数 | 平均奖励 | 通关率 |
|---|---|---|---|---|---|
| run_v1 | [1024,512] | 26.6M | 2M | 3.11 | 0% |
| run_256x2_1m | [256,128] | 6.5M | 1M | 3.62 | 0% |
| **run_512x2_1m** | **[512,256]** | **13M** | **1M** | **3.88** | **10%（3/30）** |
| run_1024x2_1m | [1024,512] | 26.6M | 1M | 3.75 | 3% |
| run_1024x3_1m | [1024,512,256] | 27.9M | 1M | 3.22 | 0% |

（对照：random 1.66 / heuristic 3.00，均 0% 通关）

### 结论

1. **[512,256] 是当前甜点**：宽度扫描呈倒 U（6.5M→3.62，13M→3.88，
   26.6M→3.75），深度是负收益（三层 27.9M 仅 3.22）。均匀词表型
   观测（大量稀疏 one-hot）下，中等宽度足够提取结构、更大的网络
   在 1M 样本下欠拟合+每步更贵。
2. **26.6M 大网 2M 步（3.11）< 同网 1M 步（3.75）**：更大网络在同一
   采样分布上继续训并未获益——不是样本量问题，是容量错配。后续
   默认网络改为 [512,256]。
3. **通关率是稀缺信号**：仅 [512,256] 出现稳定通关（3/30），与混合
   架构诊断（EXP-06）一致——Boss 短板主导通关，与前 7 场策略质量
   部分解耦。

## EXP-06 Boss 专家 + 混合架构（2026-10-08）

**状态**：✅ 第一轮完成；分布增强列为待办

### 设定

- `StsBossEnv`：入场状态模拟——牌组/遗物/药水走 run 层精确 RNG 快进

- 奖励与 run 同口径（胜 = 实际 HP/80）

| 策略 | 平均奖励 | 总胜率 | guardian | hexaghost | slime_boss |
|---|---|---|---|---|---|
| random | 0.01 | 3% | 8% | 0% | 0% |
| heuristic | 0.01 | 7% | 0% | 17% | 9% |
| boss_v1 [1024,512] | 0.07 | 23% | 31% | 17% | 18% |
| **boss_512x2_1m [512,256]** | **0.09** | **30%** | **38%** | 17% | **27%** |

### 混合架构验证（run_512x2 前 7 场 + boss_512x2 第 8 场）

- 纯 run_512x2：3.88，通关 3/30
- 混合：3.83，通关 2/30（12/30 到达 Boss 场，专家赢 2）

### 结论

1. **Boss 专家方案有效**：单独训练把 Boss 胜率从 3-7% 拉到 23-30%，
   小网络 [512,256] 再次优于大网——与 EXP-05 互相印证。
2. **混合暂未跑赢纯策略**：诊断明确——boss_env 的 HP 条件分布来自
   PPO 标定（18% 到达率），缺「满血 80 + 强牌组」的尾部样本（实测
   满血入场的 3 局专家全输）。**待办：入场 HP 对高值尾部过采样重训
   boss_v2**；届时混合架构有望突破纯策略的通关上限。
3. hexaghost 是三个 Boss 里最难的（两个网络都 17%），分裂/多段
   机制对无记忆观测最不友好——帧堆叠（已定未启用）的候选验证场。

## EXP-07 奖励口径 v2：等权战损 + 进度信用（2026-10-08）

**状态**：🔄 设计定稿并实现，重训进行中（run_512x2r_1m → 重标定 → boss_v2r_1m）

### 动机（用户纠错）

v1（逐场剩血求和）的复利计权：战斗 1 掉 1 HP 压低之后每场的贡献（直到
火堆），战斗 8 掉 1 HP 只影响自己——早期 HP 被重复计权，后期战斗在
回报中占比萎缩，激励结构偏向前期保血。

### v2 公式

- 火堆转换：`+实际回复量/80`（收到即入账；满血钳制时记 0——首版
  实现按名义 24 记，通关恒等式被虚增 0.9，测试抓出）
- 胜场：`(结算HP − 入场HP)/80 + 1/8`
- 死亡场：`−入场HP/80`（无信用）
- 截断：实际战损（保险丝路径）
- 通关：`+1`

**结构性质**（测试固化）：通关总回报 = 终局HP/80 + 1 ∈ [1.01, 2]；
死于第 k 场（0 起）= −1 + k/8 单调递增（火堆不重复计损——朴素
战损口径「火堆后死」会倒挂）；任何胜 > 任何败。

### v2 口径 baseline（30 run，种子 70..99）

| 策略 | 平均奖励 | 通关 |
|---|---|---|
| random | −0.652 | 0/30 |
| heuristic | −0.537 | 0/30 |

### 塌缩根因（本轮定位）：CARD_SELECT toggle 吸收态

强怪档塌缩后确定性策略的负局实况：**800 步卡在回合 1-4**——回合根本
没推进。逐动作解码：Power Potion 打开选卡后，策略每步选 SELECT(1)
（再选同槽=取消的 toggle 语义）→ 选/取消往复 296 次，回合永不结束。
TURN_LIMIT 按回合计，对该循环完全失效。

机制链：熵塌缩 → 确定性策略锁进「合法但零进度」的吸收态 → 值网络
被迫拟合 232 步病理轨迹的回报分布 → ev −40、advantage 纯噪 → KL→0
死定点。v1 MLP 与 EXP-09 structured 两架构在同点位先后塌缩，
**架构归纳偏置被排除为修复路径**。

### 修复：双保险丝（ACTION_LIMIT）

`sts/env.py` 新增回合内动作预算 `ACTION_LIMIT=300`（正常战斗
≤ ~250 步：25 回合 × 手牌+药水），与 TURN_LIMIT 并列判 truncated，
截断同死亡级定价。回归测试
`test_truncation_at_action_limit_select_toggle_deadlock` 钉住该场景。
