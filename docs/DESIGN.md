# 设计决策记录（DESIGN.md）

本文档记录截至 2026-10-05 已收敛的全部设计决策。修改任何决策前，先确认有充分理由并更新本文档。

## 1. 目标与范围

**目标**：训练强化学习 AI 打杀戮尖塔（一代）。核心诉求是"AI 的强化学习能力"，不是游戏复刻。

**分阶段范围**：

| 阶段 | 范围 | 状态 |
|---|---|---|
| Phase 1 | 战斗模拟器 + 固定/采样卡组的战斗策略（铁甲战士，Act 1） | **当前** |
| Phase 2 | 战斗 oracle：V(卡组, 敌人, 进场HP, 药水开关) → (E[战损], P[死)) | 规划中 |
| Phase 3 | 局外层：路线/选牌/删牌/商店/药水 | 未开始 |

## 2. 总体架构（层级式）

```
局外决策 = 受限深度 expectimax/MCTS（Phase 3，2026-10-07 修订，详见 §8）
   │  精确展开未来 1~2 场战斗内的节点（oracle 可信区间）
   │  查询: V(卡组, 敌人, 进场HP, 药水开关) → (E[战损], P[死], HP损失分布)
   │  深层叶子 → V̂(run 状态) 学习网络（自对弈闭环，AlphaZero 式）
   ▼
战斗 oracle = 泛化战斗策略 + N 次 rollout 统计（Phase 2）
   ▲  训练: MaskablePPO，卡组分布上采样，观测含卡组编码 + HP 比例
```

关键决策与理由：

- **战斗与局外分离**：战斗内短视野/高频/部分可观测，局外低频/全可观测/长规划，两者信息结构与时间尺度不同，硬塞进一个扁平策略是"整局训练不收敛"的主因（层级 RL / options 框架）。
- **局外层以搜索为主，不强求 RL**：地图全可观测、分支数小，MCTS + 战斗 oracle 的组合样本效率远高于局外 RL，可解释且免长视野 credit assignment。结构类比 AlphaZero：学习组件负责无法穷举的部分（战斗），可穷举部分交给搜索。**2026-10-07 修订**：纯搜索递归到底存在 oracle 误差复利与成本爆炸（用户识别：深层节点状态随选卡/事件推进大幅发散，机械遍历不可行），改为**受限深度搜索 + 学习型 run-value 网络 V̂**——浅层精确构造未来状态，深层叶子交给学习组件摊销，详见 §8。
- **药水**：战斗策略动作空间直接含"喝药水"（战斗内最优时机它信息最全）；局外层通过"药水开关"参数控制某场战斗是否允许用药水，规划时对比开/关代价，替代硬阈值。

## 3. 模拟器保真度策略

**放弃**：RNG 种子对齐（libGDX RandomXS128 复刻、调用顺序对齐、轨迹快照比对）。理由：种子对齐服务于可验证性而非训练；本项目要的是"足够像的 MDP"，不是同种子同轨迹。

**引擎架构（2026-10-05 决策：架构级移植 sts_lightspeed）**：战斗引擎不再自研直调式结算，改为移植 sts_lightspeed（gamerpuppy 的 C++ 复刻，MIT）的核心架构到纯 Python：

- **双端动作队列**：一切效果（卡牌、怪物招式）分解为原子动作入队（addToTop 插队 / addToBot 排队），由 BattleContext.execute_actions 主循环统一弹出结算。"结算中再触发"的卡牌交互天然由队列顺序表达，不再有直调模型的顺序歧义
- **回合生命周期**：end_turn → call_end_turn_actions → on_turn_ending（弃手牌 + UnnamedEndOfTurn）→ MonsterStartTurn（各怪格挡清零 + 起手状态）→ 逐怪 take_turn（执行意图 + 回合末 roll_move 生成下回合意图）→ after_monster_turns（回合末统一结算：状态衰减、Ritual；然后玩家回合开始）
- **层级**：`sts/combat/`（引擎，不感知具体内容）+ `sts/content/`（卡牌/怪物定义，效果表达为"向引擎入队原子动作"，对齐 lightspeed 的 constants/ + useXxxCard switch 拆分）
- **状态系统**：Power 钩子对象栈 → IntEnum + Statuses 计数容器；结算逻辑集中在引擎按固定顺序检查（对齐 lightspeed 的 status bitset 设计）
- **输入状态机**：InputState（EXECUTING_ACTIONS / PLAYER_NORMAL / …）显式建模"何时轮到玩家"
- **RNG 分流**：shuffle / monster_hp / ai / misc 四条独立流（SeedSequence.spawn 派生）——不为轨迹对齐，为固定种子回归测试对无关改动稳健

明确**不移植**（无来源或违反范围）：~~遗物~~（**2026-10-05 修订**：迁移战斗内生效遗物 ~55 个——RelicContainer 保序列表+集合查询+计数器，效果为各钩子位的固定序 if 查询，对齐 lightspeed initRelics 三桶与硬编码顺序；局外遗物（地图/商店/宝箱/营地类）仍排除）、~~药水~~（**2026-10-07 修订**：42 种药水已全量迁移——PotionDef 内容层 + use_potion/obtain_potion 引擎 API，场景经 potions 参数携带初始药水；战斗内随机获得（炼制药水卡/熵变酿制）从全池抽；Gym 动作空间扩展暂缓（引擎层完整，env 集成待训练需要时再做））、选卡界面（**注**：卡牌用到的 CARD_SELECT 选卡状态机已作为引擎能力迁移，见 2026-10-05 批次 0）、临时牌进手牌（**注**：make_temp_card_in_hand 已支持）、stance/orb（铁甲战士无）、Java Random 逐 bit 复刻、RNG 调用次数对齐（noOpRollMove 仅保留占位语义）。

**2026-10-07 对照本体反编译源码补齐批次**（sts_game_data/，V2.3.4 CFR 反编译）：兜底怪 ApologySlime + 事件变体拉格维林；卡牌补至 370/370（狂怒/灵体/噬咬/J.A.X./仪式匕首/彻悟/炼制药水）；战斗遗物 +7（蓝蜡烛/医疗箱/瓶装火焰·闪电·龙卷风/古代茶具/赌博筹码 + 药水批次的神圣树皮/玩具发条鸟/药水带）；药水 42 种全量。与源码的已知偏差逐处注明（暗之精华 0 球空转怪癖、火/爆药纯伤害管线等）。

**保留（分布级保真，对训练效果要命的部分）**：

1. 伤害/格挡管线数学：力量→易伤→虚弱→脆弱的乘算顺序与取整规则（参考 rusted-spire 的钩子链：`atDamageGive` → `atDamageReceive` → floor → clamp）
2. 信息结构：抽牌堆顺序对 agent 隐藏（见 §4）
3. 结算顺序的宏观规则：回合结束 buff 结算先后、死亡结算时机
4. 卡牌交互：进阶、消耗、Power 叠加
5. 回合末结算时机（2026-10-05 用户实测纠错后，经 Java 反编译验证）：
   - 所有敌人行动完毕后统一结算：先玩家回合末钩子、再各敌人回合末钩子
   - 临时 debuff（易伤/虚弱/脆弱）回合末 -1 层、归零移除；**敌方在敌方阶段施加的 debuff 首个回合末不递减**（Java justApplied），玩家施加的当轮就递减
   - Ritual 怪物版：回合末 +力量，施加当轮跳过（Java skipFirst）→ Cultist 黑暗打击序列 6/9/12/…（第 2 回合首击就是 6，无力量加成）
   - 乘算修饰（易伤 ×1.5 等）不在钩子内取整，floor 在管线末统一执行（Java atDamageReceive 返回浮点）

内部 RNG 直接用 numpy/torch 生成器，洗牌 Fisher-Yates，敌人意图按权重抽样——分布对即可。每个 episode 全新种子。

**验证方式（统计级，非轨迹级）**：启发式脚本 bot 在真游戏（CommunicationMod）与模拟器各打几百场同样战斗，比较胜率/平均剩余 HP/回合数分布；或对照社区 ascension 20 人类统计做 sanity check。

**数据来源**：数据层从游戏解包（CFR/Procyon 反编译一代 jar，或写 20 行 BaseMod dump mod 动态导出全量 JSON）；逻辑层以 sts_lightspeed C++ 源码为权威参照移植（其每行的结算顺序均经社区验证），wiki 数值做交叉校验。

## 4. 信息边界规格（POMDP，玩家对等）

原则：AI 不得获得多于玩家的信息。问题正确定位为 POMDP，但不上专门 POMDP 算法——观测设计正确即可，MaskablePPO 照常使用。

### 4.1 白名单（agent 可见）

- 敌人**当前回合**意图（类型 + 数值）——与游戏 UI 一致，是玩家决策核心输入
- 敌人 HP、格挡、已生效 buff/debuff、修饰符
- 手牌完整内容、能量、自身 HP/格挡/buff
- 抽牌堆/弃牌堆/消耗堆的**构成**（每种卡各剩几张，无顺序）
- 卡组、遗物持有（战斗内生效遗物的集合与公开计数器）、药水持有、回合数等元信息
- 金币持有（战斗内 Looter 偷金对玩家可见）

### 4.2 黑名单（agent 不可见）

- 抽牌堆/弃牌堆的**顺序**（编码一律计数/multi-hot，禁把内部 list 喂给编码器）
- 敌人**下一回合之后**的意图（实现保证：意图在敌人行动回合结束时才生成，观测中物理上不存在未来值）
- 环境内部任何 RNG 状态

### 4.3 自动化兜底（必须写进测试套件）

- **信息泄露审计**：同一状态下，重洗抽牌堆余牌 + 重掷未来随机流，两次观测必须逐位一致。每次新增观测特征都要跑此测试
- 评估种子与训练种子不相交，且每次评估重新随机

### 4.4 已选定的意图设定

**玩家对等**：当前回合意图可见，未来不可见（备选的"意图全隐藏"设定为主动加难的鲁棒性研究，仅可作对照实验，不作主设定）。

## 5. RL 方案

- **算法**：MaskablePPO（sb3-contrib）。动作集合随局面变化，action mask 必需
- **网络**：小 MLP 足够（观测低维结构化数值，几百维）
- **奖励**：起点为稀疏（胜/负 ±1）+ 谨慎 shaping（HP 变化等），shaping 有引入歧向策略的风险，需实验对比
- **BC 预训练（可选杠杆）**：CommunicationMod 录制轨迹 → 监督学习预训练 → PPO 微调。参考 vvsuby：BC+PPO 比 from scratch 样本效率高约 10 倍
- **评估**：固定种子几百局，对比两个 baseline——随机策略、简单启发式（如"优先打伤害最高的牌"）。没有 baseline 的胜率无意义

### 5.1 观测/动作设计要点（从第一天预留）

- **卡组可变长编码**（multi-hot / 计数向量）：Phase 2 oracle 必须能评估"没见过的卡组"，训练时就要在卡组分布上采样（按真实选牌过程生成随机演化卡组），而非每个固定卡组单独求解
- **HP 比例进观测**：让战斗策略自己条件化"满血激进 vs 残血保守"（oracle 报告按标准进场 HP，残血修正由局外层做近似）
- 战斗 oracle 输出**两个量**：E[战损] 与 P[死亡]（期望 10 但 5% 概率掉 40 的战斗比稳定掉 18 的更危险）

### 5.2 环境重构（批次 5，2026-10-07 用户决策）

引擎全量后 env 层的整体重构，四项核心决策：

- **观测编码 = 平铺计数向量**：词表键 (卡名, 升级)（368 CardDef × 2 ≈ 736 位，升级版是性能不同的牌，四堆计数必须分维），总观测 ~4500 维 int32 + `OBSERVATION_MAXIMUMS` 上界表。不采用 embedding 编码器——保持小 MLP + MaskablePPO 路线，且与 Phase 2 卡组 multi-hot 输入同构
- **训练范围 = 先铁甲全内容**：铁甲 + Act 1 全遭遇重训（对照 weak 场景 76.0 基线），四职业（职业 one-hot / stance / orb 观测段首批就建好，训练后置）
- **CARD_SELECT 候选窗口 = 10**：自回归 SELECT(i) + CONFIRM 多步完成一次选卡（引擎 `choose_cards(indices)` 直接对接）；弃牌堆大候选按稳定卡 ID 排序截前 10，**已文档化的分布级近似**
- **记忆机制 = 首轮直接帧堆叠**：stack 最近 K 步观测进网络输入（对怪招史长程推断更稳）；不引入 RNN

新增观测段：职业 one-hot×4、金币、遗物 129 multi-hot + 公开计数器（笔尖/茶具等）、药水 3~4 槽×(占用+42 one-hot)、limbo 保留区（第 4 堆，Retain 的牌上回合在手里、玩家可见）、stance/mantra、orb 槽；5b 追加：输入状态 one-hot（PLAYER_NORMAL/CARD_SELECT/SCRY——挂起态是动作路由分支，必须进观测）+ 展示窗口段（10 槽×词表 one-hot + 槽特征 + 选中标志，CARD_SELECT=稳定序候选 / SCRY=堆顶序检视牌）。新增动作段：药水（槽×[自身/自动指向+5 目标] + 姿态药水 choice）、CARD_SELECT 自回归（SELECT 再选取消 + CONFIRM 提交）、SCRY（引擎已收缩为 `keep_top_n` 单整数，0..7）；X 费沿用"全能量快照"既有近似。顺手修复 unplayable 牌（Wound/Burn/Dazed）的 action mask 缺口。

**信息边界新增两条**（进 §4.3 审计）：

- CARD_SELECT 候选顺序必须与堆内部顺序无关（Seek/Headbutt 类从抽/弃牌堆选卡，候选按稳定卡 ID 排序呈现——否则候选顺序 = 堆序 = 泄露）
- Scry 是合法例外：检视界面期间堆顶顺序可见是游戏机制本身，审计只管"检视结束后回到普通观测"

"随机可选项"（Discovery 类生成三选一）的边界澄清：选项集合呈现给玩家的那一刻起是合法可见信息（那正是决策输入），不可见的只是生成之前。

### 5.4 采样式场景与分档 policy 体系（批次 5c v3，2026-10-08 用户决策）

放弃 8 场连续 run（v2 塌缩教训），改为 `StsSampledEnv`（`sts/sampled_env.py`）：
每场独立 episode，入场状态按难度参数表采样——HP 区间（弱 60-80 / 强
40-80 / 精英 30-70 / Boss 25-70）、药水/栏概率（10/20/50/70%）、新增卡
0-2/2-5/3-7/3-8（30% 升级）、删基础打防 0/0-1/0-2/0-2、遗物 0/0-1/
0-2/0-3（源码 tier 池）。奖励 = 胜: HP/80×权重，败/截断: −入场HP/80×权重。

**分档 policy 体系（用户构想，2026-10-08）**：3 Act × 4 档（弱/强/精英/
Boss）= 12 个战斗 policy + 局外 2 个（选卡/路线，Phase 3）。调度 = 查表
policy[act][tier] 全量常驻（~600MB），逐房切换零成本。放弃跨档泛化、
换取单分布训练的稳定性——混合分布的尺度悬殊与 value 跨域崩坏（v3
实测）自动消失；对齐 Phase 3 结构（地图可见 → 专家调度是自然的）。

**战损阈值（验收标准，2026-10-08 用户设定）**：弱 ≤5 / 强 ≤12 / 精英
≤25 / Boss ≤35（胜局平均战损，人类玩家锚点）。阈值不进奖励（保持线性
口径干净），作为各 policy 的独立验收线 + 胜率下限。heuristic 现状
6.2/31.8/45.5/48.8——四档全部有实质压缩空间（弱怪 52% 压缩空间撤回
「降级 heuristic」的旧判断：战损口径下胜率饱和 ≠ 无学习价值）。

**冷启动死锁与解法（2026-10-08 受控实验链）**：全输局分布下 value 无
可学方差（ev −150）→ advantage 全噪声 → 策略确定性重播死亡轨迹。
Boss×5 尺度悬殊是混合场景的塌缩元凶（等权对照验证）；纯 Boss 场则
死于冷启动。解法 = 用户决策的 HP=1000 冷启动（boss1000 难度变体）：
1000 血下 Boss 战可赢 → value 有信号 → 一次成功（90% 胜率、全程健康）。
退火链（1000→正常血量）承接；Act 2/3 精英与 Boss 同法可复用。

**塌缩第三元凶：CARD_SELECT toggle 吸收态（2026-10-08 定位）**：
v1 轮强怪档塌缩的实况——确定性策略在 Power Potion 选卡界面每步
SELECT(1)（toggle 语义：再选同槽=取消），选/取消往复 296 次、回合
永不推进，TURN_LIMIT 按回合计对此失效。熵塌缩 → 锁进「合法但零
进度」吸收态 → 值网络拟合病理轨迹分布 → ev 崩坏 → KL 死定点。
两段修复：1) `ACTION_LIMIT=300` 回合内动作预算保险丝（与 TURN_LIMIT
并列判 truncated，同死亡级定价）；2) **SELECT 单调化**——已选槽
mask 关闭（不可取消），选卡子 MDP 成 DAG，吸收态结构上不存在；
代价 = 选卡不可反悔（近似）。架构层对照（EXP-09 structured 提取器）
证明换架构救不了——根因在环境动力学，两架构同点位先后塌缩。
附带修复：周期评估环境与训练难度一致（混合难度评估曾掩盖 Boss
专项指标）。

### 5.3 迷你局环境（批次 5c，2026-10-07 用户设定）

单场战斗之上的一层固定结构 run：**3 弱怪 → 精英 1 → 2 强怪 → 精英 2 → Boss**（8 场）；每场胜利后卡牌奖励（3 选 1 随机拿）与药水掉落，精英战后掉遗物，两次精英与 Boss 战前火堆回血 30% max_hp。所有掉落概率取自本体反编译源码（非纯随机，`sts/run_env.py` 模块头有逐条出处）。用户决策（奖励，2026-10-08 v2 修订）：**等权战损 + 进度信用**——胜场 = 净 HP 变化/80 + 存活信用 1/8，死亡场 = −入场HP/80，火堆转换 = 实际回复量/80（收到即入账，防死亡路径重复计损），通关 +1。每点战损全程等价（v1 逐场剩血求和的复利计权使后期战斗占比萎缩——用户纠错）。恒等式：通关总回报 = 终局HP/80 + 1 ∈ [1.01, 2]；死于第 k 场 = −1 + k/8 单调递增；胜败区间分离。选牌 = 前 3 场必选、后期 50% 跳过。跨场状态：HP 继承 + 燃烧之血（铁甲开局遗物）战后回 6 已联动；药水跨场携带。run 特征段（16 维：战斗序号/下一场类型）进观测——真实游戏里这是地图可见信息。terminated 只在 run 结束（死亡/通关）时为 True，中间场的胜利不是 episode 终止。

## 8. 局外层设计（Phase 3，2026-10-07 讨论定稿）

局外 AI 覆盖五个决策点：**卡牌奖励选择、事件选择、路线选择、火堆（休息/强化/特殊选项）、商店**（含宝箱）。以下决策已定稿，实现时不再重新讨论：

### 8.1 架构：受限深度搜索 + 学习型 run-value 网络

- **浅层（未来 1~2 场战斗内）精确展开**：决策节点取 max、随机节点（事件结果/? 房/卡牌奖励）按真实分布取期望、战斗节点查 oracle。规划器**构造**未来状态（树上第 5 层的战斗节点查它自己的演化后状态，不是从当前状态外推）——"后续状态与决策时差别很大"由构造消解
- **深层叶子交给 V̂**：学习网络直接估 run 状态价值。理由：oracle 逐层递归存在误差复利与成本爆炸（深层节点状态发散，机械遍历不可行——用户 2026-10-07 识别）。搜索深度落在 oracle 可信区间内（恰好是"只有下一场战损最准"这一局限的设计化利用）
- **V̂ 闭环（AlphaZero 式）**：搜索器自对弈跑完整 run → 收集 (中途 run 状态, 真实结局) 对 → 监督训练 V̂。**无手工奖励**——衡量负担转移到真实结局的 Monte Carlo 回报；run 只有 ~50 个局外决策，credit assignment 规模温和（层级结构买到的东西）
- **HP 以轻量分布传递**（3~5 分位点，非标量）：点期望会系统性低估猝死尾部风险；oracle 侧把 rollout 的 HP 损失分布直接吐出（数据本来就有）
- **估值精度观**：误差只要不翻转 argmax 即无害——决策需要正确偏序，不需要精确值

### 8.2 价值函数（双目标）

```
V(run 状态) = P(通关) + α · E[终局 HP / max_HP]
```

- P(通关) 主导（硬性量）；HP 结余为资产项（下一 Act 起点、余量缓冲）
- α 起步 0.1~0.2（过大则规划器为保血牺牲通关率，方向反转）；**α=0 vs α>0 为 Phase 3 首个对照实验**
- 若对学习组件改用 RL 口径，一律 potential-based shaping：r' = r_terminal + γΦ(s') − Φ(s)，Φ = P(通关) 估计（Ng, Harada & Russell 1999 保证不改变最优策略）；禁止任何非此形式的手工中间奖励

### 8.3 五决策点口径

| 决策点 | 方法 | 备注 |
|---|---|---|
| 路线 | expectimax over 地图 DAG；? 房/内容为真实分布 chance node | 禁用预生成结果（规划器不得变先知） |
| 选牌 | value(card) = V(卡组+card) − V(卡组)，skip 为一等动作 | **不采样未来 draft**（2026-10-07 决策）：只对当前遭遇池 + 剩余楼层结构取期望，记为已知近似，卡牌协同与演化留待升级 |

### 8.4 局外信息边界（玩家对等，扩 §4）

- 地图结构全可见（与游戏 UI 一致）；? 房/事件/卡牌奖励的**内容在生成前不可见**，生成后（选项呈现那一刻起）合法可见
- **审计义务**：同一局外状态下重掷全部内容生成流（? 房/事件分支/卡牌奖励/商店库存），规划器估值必须不变——§4.3 局外版，陷阱 6 的推广

### 8.5 工程要点

- **搜索器直接调模拟器 API，不 Gym 化**（Gym 是学习组件/对照实验的接口）；核心 API 需求 = 快照/回滚（snapshot/restore，copy-on-write 或不可变结构）
- **oracle 调用是成本瓶颈**：结果缓存键 = (卡组 multi-hot 规范化哈希, 遭遇, HP 桶化~5%, 药水开关)；MCTS 渐进加深；rollout 批量化并行喂网络
- **局外模拟器可与 Phase 2 并行开工**（不依赖 oracle，先用启发式选牌自测完整 Act 1）
